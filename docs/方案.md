# 机房签到系统方案（第一阶段）

## 目标与范围

胖终端机房内，教师机发布一次班级签到，学生机使用本人 18 位居民身份证号码提交。教师机在服务端比对班级学生信息、去重并保存记录。第一阶段只建立可运行工程、双端界面、局域网通信边界、场次持久化和后端适配器接口；**目前不接入真实学生数据，也不会返回模拟签到成功**。

## 架构

```text
学生端 Electron/Vue
  └─ preload API → 主进程 → 机房局域网 HTTP → 教师机签到服务
                                    ├─ 场次与签到记录（本地 JSON，后续可迁移 SQLite）
                                    └─ StudentDirectory 适配器 → 学校后端（待接入）
教师端 Electron/Vue ─ preload API ───────┘
```

- 教师端在机房局域网提供签到服务；学生端首次启动后通过局域网广播自动发现教师端，不需要逐台修改配置。
- 教师机内嵌 Node HTTP 服务，界面用 3～5 秒轮询。先验证可靠性，WebSocket 暂不引入。
- 教师机是签到判定和记录写入的唯一入口。学生端不保存完整证件号。
- `StudentDirectory.findByIdCard(idCard, classId)` 是学校后端接入点，需使用学校现有认证方式，并限定班级范围。
- 学生端每次签到从操作系统读取电脑名称并发送给教师端。记录按场次保存学生编号、姓名、电脑名称、时间、身份证后四位；新场次不会清除旧记录。不保存完整身份证号。教师机数据文件需要由机房账号权限保护。
- 断网时显示错误并允许重新提交；第一阶段不离线缓存身份证号。没有实时校验能力时不判定签到成功。
- 身份证号码只能匹配名册中的身份，不能证明输入者就是本人。防代签需结合教师现场核验或学校已有的强身份认证；动态课堂码只限制远程提交，不能独立解决代签。

## 签到流程与接口

1. 教师机输入班级编号与名称，开始场次，生成随机场次 ID。
2. 学生机轮询只包含场次 ID、班级名称及状态的公开场次接口。
3. 学生输入身份证号。主进程向教师机发送场次 ID、证件号和电脑名称。
4. 教师机校验证件号格式及校验位，调用学校后端核对当前班级，按学生编号去重，写入本地记录后返回结果。
5. 教师端定时刷新记录。结束场次后拒绝新签到。

| 路径                    | 用途           | 当前状态                                   |
| ----------------------- | -------------- | ------------------------------------------ |
| `GET /health`           | 服务存活检查   | 已实现                                     |
| `GET /api/v1/session`   | 学生端读取场次 | 已实现                                     |
| `POST /api/v1/checkins` | 提交身份证签到 | 已实现输入校验；名册适配器未配置时返回 503 |

提交请求形状：`{ "sessionId": "...", "idCard": "...", "stationId": "..." }`。状态码类型见 `src/shared/contracts.ts`。

## 部署与锁屏

开发默认仅监听 `127.0.0.1:41731`，只供同机联调。打包后的教师端默认监听 `0.0.0.0:41731`，并在 UDP 41732 接收局域网发现广播；学生端自动发现教师机的内网地址后，通过 HTTP 访问签到服务，无需配置证书或逐台填写地址。该模式假设机房网络可信且与公网隔离；教师机防火墙应只允许机房网段访问 TCP 41731 和 UDP 41732。自动发现适用于同一广播网段，跨 VLAN 网络需由网络侧转发发现流量或提供静态服务发现记录。

学生端窗口启动后使用无边框 kiosk 全屏，并拦截普通窗口关闭；教师结束活动场次后，学生端自动退出回到桌面。教师服务网络中断时，学生端保持当前画面并等待恢复连接。Electron kiosk 和窗口关闭拦截不能替代 Windows 系统策略，也无法保证屏蔽所有系统级快捷键。需要更强限制时，先核实机房系统版本与管理软件：Windows Enterprise/Education 可评估 Shell Launcher、应用控制和 Keyboard Filter 的组合；Windows Pro 需另选机房管理软件或变更终端策略。

## 后端接入前要确定

1. 学校后端地址、认证方式、证书信任方式；教师机是否可访问后端。
2. 查询接口形状：按身份证号和班级编号精确查找学生，返回稳定学生 ID、姓名、班级 ID；是否支持整班名单及未签到统计。
3. 班级 ID 来源、同名学生处理、转班学生规则、同一学生跨机器重复签到规则。
4. 学生机准入方式：设备登记凭据、服务端限流与审计。当前 HTTP 接口尚未实现设备认证，因此不能在接入真实名册后直接开放到全机房。
5. 签到记录保留期限、导出字段、删除规则。未签到名单和 Excel 导出需在整班名单接口确定后实现。
6. 学生端的正常退出方式已定为教师结束场次后自动退出；部署时还需安排管理员在网络故障、进程崩溃和终端维护时的恢复流程。

## 验收顺序

1. 同机运行教师端与学生端，验证场次同步、无效身份证返回、未配置名册返回 503、教师端无虚假记录。
2. 确认后端接口后实现 `StudentDirectory`，先用测试班级验收正确、重复、非本班和后端故障情形。
3. 实现设备认证、限流和教室网络测试。
4. 最后依据 Windows 版本做机房锁屏试点与维护恢复演练。
